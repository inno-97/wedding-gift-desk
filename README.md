# 축의대 (축의금 장부)

결혼식 축의대에서 여러 명이 폰으로 동시에 봉투를 등록하는 웹 앱입니다.
설치 없이 폰 브라우저로 접속해서 사용합니다.

| | |
|---|---|
| **접속 주소** | https://wedding-ledger-505b1.web.app |
| **지원 환경** | 아이폰 사파리, 안드로이드 크롬 (PC 브라우저도 가능) |
| **필요한 것** | 인터넷 연결 (와이파이가 불안정하면 LTE/5G 권장) |
| **로그인** | 없음. 장부 링크를 아는 사람만 해당 장부에 접근 |

---

## 사용법

### 1. 준비 (예식 전, 담당자 1명)
1. 접속 주소에서 **장부 만들기**를 누릅니다.
   - 양가 명부가 섞이지 않도록 **신랑 측 / 신부 측 장부를 따로** 만듭니다.
   - "처음 받은 식권 수"를 넣으면 잔여 식권이 자동으로 계산됩니다. 비워 둬도 되고, 나중에 설정에서 바꿀 수 있습니다.
2. 만들어진 장부 화면 오른쪽 위 **☰ → ⚙︎ 장부 설정**에서 필요한 값을 정합니다.
   - **기본 식권 수**: 등록할 때 처음 채워지는 식권 수 (기본 1)
   - **기본 금액**: 보통은 비워 두세요 (봉투를 받을 때는 금액을 모르므로)
3. 같은 설정 화면의 **[링크 복사]**로 장부 링크를 복사해 함께 등록할 분들에게 보냅니다.
   - 링크를 받은 사람은 누구나 등록·수정할 수 있습니다. **단체방에는 올리지 마세요.**

> 장부 링크(`/l/…`)는 한 번 잃어버리면 다시 찾기 어렵습니다. 만든 사람 폰의 처음 화면 "최근 연 장부"에 남지만, 별도로 메모해 두세요.

### 2. 접수 중 (봉투 받을 때)
```
(✕) 신부 측 ●            봉투 12  식권 20/잔여 100  ☰
┌──────────────────────────────────────────────┐
│ 봉투번호 자동      이름 필수          ⚠ 이름중복  │
│ [  13  ]       [ 홍길동                     ] │
│ 식권                          [ − ]  1  [ + ] │
│ 관계  [친구] [직장] [친척] [가족]               │
│       [학교] [지인] [부 지인] [모 지인]          │
│ ▸ 관계 직접입력 · 메모                          │
├──────────────────────────────────────────────┤
│ 축의금 (비워 두고 마감 때 입력)                  │
└──────────────────────────────────────────────┘
[                    등록                     ]
```
1. 화면의 **봉투번호를 실제 봉투에 똑같이 적습니다.** 번호는 등록할 때마다 자동으로 1씩 올라갑니다.
2. **이름**을 입력합니다 (필수). 모르면 "미상"으로 적고 메모를 남깁니다.
3. **식권** 수를 −/+로 맞추고, **관계** 버튼을 누릅니다 (선택).
   - 대리 전달, 단체 봉투, 식권 추가 같은 특이사항은 "관계 직접입력 · 메모"에 적습니다.
4. **[등록]**을 누릅니다. 이름 칸에서 키보드의 완료/엔터를 눌러도 등록됩니다.
5. 상단에 `13번 등록 · 홍길동 · 식권 1` 알림이 뜨면 저장된 것입니다.

**알아둘 것**
- **⚠ 이름중복**: 같은 이름이 이미 있다는 표시입니다. 등록은 되며, 관계나 메모로 구분해 주세요.
- **번호가 겹치면**: 다른 폰이 같은 번호를 먼저 등록한 경우 빨간 알림과 함께 번호가 다음 번호로 바뀝니다. **봉투 번호를 바뀐 번호로 고쳐 적고** 다시 [등록]을 누르세요.
- **연결 상태**: 장부 이름 옆 초록 점(●)이 정상 연결입니다. `연결 끊김 · 저장 불가`가 뜨면 등록이 막히니, 연결된 뒤 다시 누르세요 (입력 내용은 남아 있습니다).
- 금액은 하객 앞에서 확인하지 않습니다. 접수 때는 비워 두세요.

### 3. 마감 (금액 입력·정산)
1. **☰ → 목록 · 합계**로 이동합니다.
2. **[금액 미입력]** 필터를 누르고 첫 봉투를 엽니다.
3. 봉투를 열어 금액을 확인하고 빠른 금액(10·15·20·30·50·100만)이나 ±5만, 직접 입력으로 넣은 뒤 **[저장]**을 누릅니다.
   - 저장하면 **다음 금액 미입력 봉투가 자동으로 열립니다.** 봉투가 없으면 [건너뛰기].
   - 금액 칸에 "15만"처럼 입력해도 150,000원으로 바뀝니다.
4. 목록 맨 위 **합계 카드**를 누르면 합계가 보입니다 (기본은 숨김).
5. **봉투 수 = 목록의 봉투 수**인지, 식권 잔여가 맞는지 2명이 함께 대조합니다.
6. 목록 맨 아래 **[CSV 내려받기]**로 정산 파일을 받아 혼주에게 전달합니다.
   - 열: 봉투번호, 성명, 관계, 식권, 금액, 메모, 상태(삭제 여부), 등록시각 / 마지막 줄에 합계

### 수정·삭제
- 목록에서 봉투를 누르면 수정 화면이 열립니다 (축의금 입력이 맨 위).
- **번호 변경**: 봉투번호를 바꿔 저장하면 이동됩니다. 이미 있는 번호로는 바꿀 수 없습니다. 실제 봉투 번호도 고쳐 적어 주세요.
- **삭제**: 수정 화면의 "이 봉투 삭제". 실제로 지워지지 않고 숨겨지며, 목록의 **[삭제됨]** 필터에서 **복구**할 수 있습니다.

## 운영 원칙 (축의대 매뉴얼 요약)
- 양가 장부·봉투·식권은 섞지 않는다 → 장부를 측별로 따로 만들어 사용
- 하객 앞에서 봉투를 열거나 금액을 묻지 않는다 → 금액은 마감 때 입력
- 자리를 비울 땐 인계하고 봉투함을 잠근다
- 입금 확인 없는 계좌이체 요청·캡처 화면은 현금으로 기록하지 않는다 → 메모에 따로 표시
- 성명·금액이 담긴 명부(링크, CSV)는 단체방에 공유하지 않는다

## 개인정보
- 장부 링크(UUID)를 모르면 장부를 볼 수 없고, 장부 목록 조회도 막혀 있습니다.
- 폰에는 명부를 저장하지 않습니다. 탭을 닫으면 사라집니다. (처음 화면의 "최근 연 장부"에는 장부 이름과 링크만 그 폰에 남습니다)
- 행사가 끝나면 링크를 받은 분들께 링크 삭제를 부탁하세요.

## 개발자용

정적 웹(HTML/JS/CSS, 빌드 없음) + Firebase Hosting + Cloud Firestore(서울 리전). 서버 코드는 없습니다.

```
public/            화면 (index.html, app.js, style.css, firebase-config.js)
firestore.rules    접근 규칙
firebase.json      Hosting 설정 (/l/** → index.html)
```

### 데이터 구조
```
ledgers/{uuid}                 title, ticketsInitial, defaultTickets, defaultAmount, createdAt, updatedAt
ledgers/{uuid}/entries/{no}    no, name, relation, tickets, amount, memo,
                               deleted, movedTo, createdAt, updatedAt
```

### 보안 규칙 요약
- 장부: UUID 형식만 생성 가능, 목록 조회·삭제 금지
- 봉투: 문서 ID = 봉투번호 → 같은 번호는 하나만 존재
  - 신규 등록이 기존 봉투를 덮어쓰려 하면 `createdAt` 불일치로 거부 (삭제된 번호는 재사용 허용)
  - 운영 서버에서 3대 동시 등록 × 20회 검증 → 매번 1대만 성공
- 이름 필수(공백 불가), 식권 0–100, 금액 0–1억, 문자열 길이 제한, 실제 삭제 금지

### 로컬 실행 (에뮬레이터, JDK 21 필요)
```sh
PATH=/opt/homebrew/opt/openjdk@21/bin:$PATH firebase emulators:start --project demo-wedding --only firestore,hosting
# → http://127.0.0.1:5050  (localhost에서 열면 자동으로 에뮬레이터 사용)
```
※ 에뮬레이터는 동시 요청의 규칙 평가가 운영과 달라, 동시 등록 테스트는 운영 서버에서 해야 합니다.

### 배포
```sh
firebase deploy --only firestore:rules,hosting
```
보안 규칙은 배포 후 반영까지 1–2분 걸릴 수 있습니다.

### DB 조회 (관리자)
Firebase 콘솔 → Firestore → `ledgers / {장부ID} / entries`
https://console.firebase.google.com/project/wedding-ledger-505b1/firestore/databases/-default-/data
콘솔에서의 수정은 보안 규칙을 거치지 않으므로 조회만 하고, 수정은 앱에서 하세요.
